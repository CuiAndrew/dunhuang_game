# 敦煌逃亡 Q 版美术重塑设计

## 背景

当前版本已经通过 `ThemeRegistry` 接入敦煌主题，但实际呈现仍主要是低段数胶囊体、球体、盒体和锥体，材质只有平面颜色与少量程序纹理。人物、环境、障碍、道具和 UI 缺少统一的 Q 版比例、轮廓、纹样和层次，因此运行画面更像低模占位稿，而不是完整的敦煌视觉。

本次重塑只改变视觉组合层，不改变 Runner、碰撞、道具类型、轨道、对象池或状态机。所有新视觉仍由主题工厂提供，未来可以用同一接口替换上海外滩主题。

## 目标与边界

### 目标

1. 让玩家在菜单截图和开始后的前 3 秒内能明确感知“敦煌 Q 版沙海逃亡”。
2. 让 Runner、追兵、五类障碍、四类道具和五类环境变体拥有一眼可辨的轮廓与语义。
3. 让场景拥有前景、中景、远景和暖冷光层次，减少深色低模堆叠造成的“脏”和“空”。
4. 让 UI 与 3D 画面共享同一组壁画色、纸张色、墨色和金色令牌，并在窄视口保持可读。
5. 保留当前主题契约，新增的纹样、纹理和视觉辅助数据不能渗入 gameplay 系统。

### 非目标

- 本次不重写移动、换道、跳跃、滑铲、碰撞和得分规则。
- 本次不引入远程图片、字体、模型或音频依赖；本地插画由主题清单声明，并保留程序化回退。
- 本次不实现上海外滩主题，只保留明确的替换边界。
- 本次不追求写实材质或复杂后处理，优先保证 Q 版轮廓、层次和性能。

## 视觉方向

### 核心气质

“壁画里跑出来的小行者”：圆润、温暖、带一点神话感，但轮廓要简洁，避免把多个装饰堆成噪点。唯一的高识别签名是 Runner 的飞天飘带与圆形金色光环；其他元素围绕它提供道路阅读和节奏反馈。

### Q 版令牌

| 令牌 | 值 | 用途 |
| --- | --- | --- |
| muralBlue | `#244B7A` | 夜空、石窟内壁、护盾主色 |
| turquoise | `#3D9B9B` | 祥云、布幡、磁铁辅助色 |
| vermilion | `#D84B35` | 长袍、障碍警示、主按钮 |
| apricot | `#F3C77B` | 沙丘高光、面部、暖光 |
| muralGold | `#E8B23A` | 光环、铜钱、纹样、焦点 |
| paper | `#F6E7C8` | UI 纸张、石膏、文字 |
| ink | `#211C24` | 轮廓、阴影、危险状态 |
| caveNight | `#172536` | 场景底色和深层雾 |

当前 `Palette` 中的 gameplay 语义令牌继续保留；上述令牌作为敦煌适配器的视觉别名或扩展字段，不能让 gameplay 依赖具体颜色名称。

### 形状语言

- 轮廓优先使用圆角、弧线、扇形、云头和敦煌边饰，减少裸露的轴对齐方块。
- 重要交互物使用“主体 + 金色边框 + 一处红色/蓝绿色识别色”的三层结构。
- 环境采用大色块剪影和少量高对比纹样，避免每个远景物体都有细碎细节。
- 道具与障碍保持正面可读，不能因为装饰影响碰撞尺寸的理解。

## 视觉系统设计

### 主题资源层

`DunhuangTheme` 继续是唯一的美术组合入口。新增或调整的资源包括：

- `Palette`：补充 Q 版令牌和 UI 对应的 CSS 变量映射。
- `Textures`：提供纸张、壁画、祥云、沙纹、石窟边饰和天空渐变等可复用 CanvasTexture；按 `themeId:name` 缓存。
- `Props`：保留现有池化 API，在内部改为可复用的圆润几何、轮廓层和纹样层。
- `DunhuangTheme.scene`：提供暖光/冷光比例、远景层颜色和 Q 版天空纹理名等场景令牌。
- 本地 PNG 资产仅通过 `DUNHUANG_THEME.assets` 声明，背景、角色帧、障碍/道具和 HUD 不直接写死资源路径；上海外滩可提供自己的同形资产树。

主题工厂仍返回现有语义 API：

- Runner：`root`、`leftLeg`、`rightLeg`。
- 障碍：`setType()`、`userData.obstacleType`、`userData.heightOffset`。
- 道具：`setType()`、`userData.kind`。
- 环境：`setKind()`、`userData.activeKind`。

### Runner 与追兵

Runner 使用“大头、短身、飘带、光环、腰封、两条可动画短腿”的比例。脸部只保留两个深色眼点和一个暖色面部区域，保证远景仍能识别。飘带采用两段弧形或扭带几何，并带轻微摆动；光环使用带透明度的金色纹样盘，不再是单一平面圆片。

追兵改为“圆润石兽”轮廓：大额头、短角、宽嘴、金色眉饰和两点朱砂眼。主体用蓝灰石色，边缘用暖色轮廓层，避免目前的深色多面体在夜景里消失。

### 场景层次

场景分成四层：

1. 远景：蓝紫天空、月轮、低对比云带和洞窟剪影。
2. 中景：沙丘、石窟/寺门、经幡和远处灯火，采用暖色边缘光。
3. 近景：道路两侧的沙纹、石灯、壁画边饰和少量飘动布幡。
4. 交互层：障碍、铜钱、护盾、加速印章和磁铁，使用金色或朱砂色形成明确焦点。

环境变体映射：

- `DUNE`：圆弧沙丘、金色风纹、局部纸张纹理。
- `TEMPLE`：拱门、层叠檐口、朱砂门楣与小型壁画块。
- `CAVE`：深蓝石窟拱口、暖色洞内壁画。
- `LANTERN`：石灯柱、暖金灯芯、红色小檐。
- `FLAG`：青绿色经幡、金色穗边、轻微摆动。

### 障碍与道具

障碍保留五类 gameplay 语义，但视觉重新分层：

- `BEAM`：朱砂横梁、金色端饰和云头纹。
- `PILLAR`：蓝灰石柱、朱砂柱顶、金色底座。
- `FIRE`：圆形火盆、朱砂火焰、金色内焰和暖光晕。
- `GAP`：墨色断层、金色沙缘、远处蓝色深度面。
- `LOW_BARRIER`：纸白矮墙、朱砂顶部、青绿色支脚。

道具统一使用“徽章式”构图：

- `COIN`：敦煌铜钱、方孔、内圈纹样和金色闪点。
- `SHIELD`：蓝绿色护符、金色藻井环和中心宝石。
- `BOOST`：朱砂印章、金色飘带和速度纹。
- `MAGNET`：金色半环、朱砂端帽和吸附线。

### UI

UI 从普通半透明矩形改为“壁画纸片 + 墨色内衬 + 金色细边”的体系：

- 菜单标题面板增加洞窟拱形上缘、纸张颗粒和一块小型飞天/祥云纹样。
- “开始逃亡”和“再来一次”使用朱砂印章式主按钮，悬停/聚焦时出现金色边缘和轻微压印反馈。
- 距离、铜钱、最高分使用小型牌匾徽章，图标旁同时保留文字，避免只靠颜色或符号传达。
- 暂停、静音和结果页沿用同一纸张/墨色体系，按钮尺寸和焦点样式保持一致。
- `prefers-reduced-motion` 下保留状态变化，关闭飘带、灯火和徽章呼吸动画。

## 技术与性能约束

- 继续使用 Three.js r169、程序化几何和 CanvasTexture，不新增运行时网络依赖。
- 预建并缓存同主题的 geometry/material/texture 原型；对象池实例只 clone 原型并切换变体。
- 远景使用低复杂度剪影，近景才使用纹样层；不得在每帧创建 geometry、material 或 canvas。
- 保持当前性能降级策略，低帧率时减少环境密度和阴影质量，但不隐藏 Runner、障碍或道具。
- UI 保持原生按钮与现有可访问名称，窄视口至少验证 640×480。

## 验收与测试

自动化测试新增或更新：

- 断言 Q 版主题令牌、场景令牌和纹理名称通过 `ThemeDefinition`。
- 断言所有视觉变体仍拥有原有语义 API 和碰撞元数据。
- 断言同主题对象池共享 geometry/material/texture 资源。
- 断言 UI 关键 CSS 变量、按钮名称和 reduced-motion 规则存在。

浏览器验收：

- 菜单截图能辨认纸张拱形面板、Q 版 Runner、敦煌色天空和主按钮。
- 开始后 3 秒内能辨认 Runner、道路、至少两种环境、障碍和铜钱。
- 暂停、继续、重开、方向键和窄视口流程不受视觉改动影响。
- warn/error 日志为空，`npm test` 全部通过，设计审计无阻塞发现。

## 主题替换边界

未来的上海外滩主题只需要新增一个主题定义，替换 palette、scene tokens、texture set 和六个视觉工厂。它必须继续返回相同的 Runner/障碍/道具/环境语义 API，不能修改 gameplay 的类型字符串、碰撞高度、对象池容量、轨道或状态转换。
